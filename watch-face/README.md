## Alpha 7.6.11.2: moving black-dot AOD mask

This revision keeps the survey grid (GridOverlay / GridInAod) separate and
adds a genuine **opaque black pixel mask** for AMOLED AOD.

* `Moving AOD black-dot mask`: Off / Sparse (11%) / Balanced (25%, default) /
  Strong (44%). Percentages refer to the share of pixels masked in the tile,
  **not** a guaranteed reduction in OLED wear.
* Every Garmin AOD one-minute redraw chooses the next of four dot phases.
  The dot pixels are opaque black and the remainder of each tile is fully
  transparent; the mask never adds illuminated pixels to the picture.
* AOD time, date, sunrise/sunset glyphs and DEM horizon no longer shift their
  drawing coordinates for burn-in. Only the dot mask phase shifts.
* Preserve the existing semi-transparent surveying grid as a separate
  foreground visual (and separately opt-in in AOD).
* 60x60 PNG tiles keep each redraw to ~64 drawBitmap operations instead of
  thousands of rectangle draws. All optional code has graceful exception
  handling; terrain reception/rendering was not changed.

**Safety limitations:** This is experimental visual pixel-occlusion, not a
verified burn-in-prevention method. Garmin already enforces AOD brightness /
pixel limits and may perform its own protections. A mask that switches once a
minute does not eliminate burn-in risk, and leaving bright fixed shapes on AOD
for long periods still causes nonuniform wear. Test with Garmin Simulator
Always On and screen heat map before treating it as safe for long-term use.

# YAMAKAGE Watch Face — v0.1.0-alpha7.2-safe

Experimental standalone Garmin watch-face adaptation of **YAMAKAGE** by Ichimura Tomoo.

The original YAMAKAGE device app remains the full interactive experience. This watch face is intended to be useful on its own while progressively enhancing itself when the full app/backend can provide richer terrain-aware data.

## Alpha 7 highlights

- fēnix 8 Pro 47/51 mm target (454×454 AMOLED)
- standalone cached GPS workflow via `Activity.Info.currentLocation`
- Garmin location-based sunrise/sunset via `Weather.getSunrise()` / `Weather.getSunset()`
- **true location/time-based solar marker** using a lightweight NOAA-style azimuth/elevation calculation
- original YAMAKAGE sunrise/sunset icon-font glyphs
- improved AOD event layout: icons and times now use separate rows
- **Dim always-on display** option
- **Show bottom status** option
- existing options retained:
  - Show YAMAKAGE label
  - Show time colon
  - Show seconds
- full YAMAKAGE app detection by manifest ID
- press the lower/terrain area to launch the full YAMAKAGE app when installed
- subscriber-side Garmin Complications bridge for future terrain-aware sunrise/sunset publishing

## Data sources

### Standalone mode
The face caches a recent location exposed by Garmin after a GPS activity has acquired a fix. It does not start GPS itself. Standard geometric sunrise/sunset is calculated using Garmin Weather APIs for the cached coordinate.

The upper sun marker now uses latitude, longitude, and the current UTC time to calculate approximate solar azimuth and elevation. This is different from alpha 6, which only moved the icon by percentage of the sunrise-to-sunset interval.

### Enhanced YAMAKAGE mode
Alpha 7 now includes the **watch-face subscriber side** of a Garmin custom Complications bridge. A future update to the full YAMAKAGE Device App can publish terrain-adjusted sunrise/sunset values under the reserved labels documented in `COMPANION-INTEGRATION.md`; the face will discover, subscribe to, cache, and prefer them while retaining Garmin horizon times as a fallback. The current/original Device App does not publish these complications yet.

The mountain silhouette in alpha 7.1 is still intentionally **stylized**, not claimed to be the real terrain around the saved coordinate. The original app/backend produces the real azimuth terrain profile; that should be bridged rather than approximated.
